To use MD5 checksums with rsync, you can either rely on rsync's built-in block-level checksum validation during synchronization or manually generate an external text-based manifest file using md5sum.
By default, rsync optimizes transfers by using a "quick check" algorithm that compares file sizes and modification times (mtime). If they match, rsync skips the file without checking the underlying contents.

Option 1: Force rsync to Use Internal Checksums (-c or --checksum)

If you want rsync to read file contents and compute hashes on both the source and destination to detect silent data corruption or content updates that didn't change the modification time, use the -c / --checksum flag.
• Synchronize and overwrite based on content hashes:bash
rsync -avc /path/to/source/ /path/to/destination/
Use code with caution.
• Verify if two directories match (Dry Run):
If you just want to compare the files without performing an actual file copy, add --dry-run. rsync will print a list of files that differ by MD5:bash
rsync -avc --dry-run /path/to/source/ /path/to/destination/
Use code with caution.
⚠️ Performance Note: The -c flag requires heavy disk I/O on both sides because rsync must read every single file completely to compute the checksums before deciding whether to transfer data. For massive directories, this will slow down operations.

Option 2: Generate and Verify an External md5sum Manifest

If you want to keep an audit trail or double-check a copy process independently of rsync, you can generate a standard .md5 text manifest before the transfer and verify it after completion.
1. Generate the MD5 baseline list in the source directory:
------------------------------------------------
bash
cd /path/to/source/
find . -type f -exec md5sum {} + > manifest.md5
------------------------------------------------
Use code with caution.
2. Use rsync to copy your data (including the manifest):
-------------------------------------------------
bash
rsync -av /path/to/source/ /path/to/destination/
-------------------------------------------------
Use code with caution.
3. Verify the files at the destination:
-------------------------------------------------
bash
cd /path/to/destination/
md5sum -c manifest.md5
-------------------------------------------------
Use code with caution.
The -c flag for md5sum tells it to read the generated file, compute the live hashes of the copied items, and output OK for successful matches.

Comparison Matrix


Approach	Best Used For	Primary Benefit	Primary Drawback
Default rsync	Rapid day-to-day backups.	Incredibly fast; only checks size and timestamps.	Can miss silent file corruption if sizes stay identical.
rsync -c	Detecting data degradation across storage arrays.	Pure, safe transfer engine automation.	Extreme disk I/O; slow execution speeds.
External md5sum Manifest	Multi-hop migrations or cold storage auditing.	Provides a permanent, date-stamped validation blueprint.	Requires a two-step shell script workflow.
